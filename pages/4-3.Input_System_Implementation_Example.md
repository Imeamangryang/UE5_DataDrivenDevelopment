# 입력 시스템 구현 예제

이제 Unreal Engine에서 데이터를 저장하는 방식 중 하나인 Data Asset과 Enhanced Input System에 대해 알아보았으니, 이를 활용하여 간단한 입력 시스템을 구현해보도록 하겠습니다.

## 프로젝트 생성

먼저 Unreal Engine에서 새로운 프로젝트를 생성합니다. 프로젝트 유형은 `Games`로 선택하고, 템플릿은 `Blank`로 선택합니다. 프로젝트 이름은 `UE5_DDD`로 지정하겠습니다.

## Gameplay Tag 정의

먼저 입력 시스템과 Gameplay Tag를 연결하기 위한 Data Asset을 만들어보겠습니다. 이 Data Asset은 각 입력 액션이 어떤 Gameplay Tag와 연결되는 지를 정의할 것입니다.

> Gameplay Tag는 문자열 기반의 계층형 식별자 시스템으로, Unreal Engine에서 다양한 시스템 간의 상태와 이벤트를 데이터 중심으로 관리하기 위해 사용됩니다.  

아래와 같이 입력 시스템에서 사용할 Gameplay Tag를 선언합니다.

```cpp
#pragma once  
  
#include "NativeGameplayTags.h"  
  
namespace InputGamePlayTags  
{  
    UE_DECLARE_GAMEPLAY_TAG_EXTERN(InputTag_Action_Move);  
  
    UE_DECLARE_GAMEPLAY_TAG_EXTERN(InputTag_Action_LightAttack);  
    UE_DECLARE_GAMEPLAY_TAG_EXTERN(InputTag_Action_HeavyAttack);  
}
```

이후 `.cpp` 파일에서 실제 Gameplay Tag를 정의합니다.

```cpp
#include "InputGamePlayTags.h"  
  
namespace InputGamePlayTags  
{  
    UE_DEFINE_GAMEPLAY_TAG(InputTag_Action_Move, "Input.Action.Move");  
  
    UE_DEFINE_GAMEPLAY_TAG(InputTag_Action_LightAttack, "Input.Action.LightAttack");  
    UE_DEFINE_GAMEPLAY_TAG(InputTag_Action_HeavyAttack, "Input.Action.HeavyAttack");  
}
```

Gameplay Tag는 일반적으로 다음과 같은 계층 구조로 구성합니다.

![](../assets/Pasted%20image%2020260526113556.png)

또한 Gameplay Tag를 입력 시스템과 함께 사용하면 단순히 “어떤 키가 눌렸는가”를 처리하는 것이 아니라, “어떤 행동(Action)이 발생했는가”를 기준으로 시스템을 설계할 수 있게 됩니다.

예를 들어 마우스 좌클릭이 공격인지 상호작용인지는 상황에 따라 달라질 수 있습니다. 하지만 입력 시스템에서는 단순히 `Input.Action.MouseLeft`라는 행동만 전달하고, 실제 동작은 다른 시스템에서 처리하도록 분리할 수 있습니다.

이는 입력과 게임 로직 사이의 결합도를 낮추고, 보다 유연한 Data-Driven 구조를 만드는 데 큰 도움이 됩니다.

## Input Config Data Asset 정의

이제 입력 시스템과 Gameplay Tag를 연결하는 `Input Config Data Asset`을 정의해보겠습니다.

앞서 설명했듯이 Enhanced Input System은 `Input Action`을 중심으로 동작합니다. 하지만 실제 게임 로직에서는 단순히 Input Action 자체보다는 “어떤 행동이 발생했는가”를 기준으로 처리하는 경우가 많습니다.

예를 들어 입력 시스템에서는 `IA_Move`라는 Input Action이 존재하더라도, 실제 게임 코드에서는 이를 `Input.Action.Move`라는 Gameplay Tag 기반으로 처리하는 것이 더 유연한 구조가 됩니다.

이를 위해 이번에는 Input Action과 Gameplay Tag를 서로 연결하는 Data Asset을 정의하겠습니다.

```cpp
#pragma once  
  
#include "CoreMinimal.h"  
#include "Engine/DataAsset.h"  
#include "GameplayTagContainer.h"  
#include "InputConfig.generated.h"  
  
class UInputAction;  
  
USTRUCT(BlueprintType)  
struct FTaggedInputAction  
{  
    GENERATED_BODY()  
  
public:  
    UPROPERTY(EditDefaultsOnly, BlueprintReadOnly)  
    TObjectPtr<const UInputAction> InputAction = nullptr;  
  
    UPROPERTY(EditDefaultsOnly, BlueprintReadOnly)  
    FGameplayTag InputTag;  
};  
  
UCLASS()  
class UE5_DDD_API UInputConfig : public UDataAsset  
{  
    GENERATED_BODY()  
    public:  
    UPROPERTY(EditDefaultsOnly, BlueprintReadOnly)  
    TArray<FTaggedInputAction> InputActions;  
  
    const UInputAction* FindInputActionByTag(const FGameplayTag& InputTag) const;  
};
```

`FTaggedInputAction` 구조체는 다음 두 가지 데이터를 함께 저장합니다.

| 변수            | 설명                                     |
| ------------- | -------------------------------------- |
| `InputAction` | 실제 Enhanced Input System의 Input Action |
| `InputTag`    | 해당 Input Action과 연결될 Gameplay Tag      |

현재는 하나의 Input Action이 어떤 Gameplay Tag와 연결되는 지를 데이터 형태로 정의하는 구조입니다.

이를 통해 다음과 같은 매핑이 가능해집니다.

| Input Action   | Gameplay Tag             |
| -------------- | ------------------------ |
| IA_Move        | Input.Action.Move        |
| IA_LightAttack | Input.Action.LightAttack |
| IA_HeavyAttack | Input.Action.HeavyAttack |

`UInputConfig`는 이러한 매핑 정보를 배열 형태로 저장하는 Data Asset 역할을 수행합니다.

또한 `FindInputActionByTag()` 함수를 통해 특정 Gameplay Tag에 대응되는 Input Action을 검색할 수 있도록 구현합니다.

```cpp
#include "InputConfig.h"  
#include "InputAction.h"

const UInputAction* UInputConfig::FindInputActionByTag(const FGameplayTag& InputTag) const
{
	for (const FTaggedInputAction& Action : InputActions)  
	{  
	    if (Action.InputAction && Action.InputTag.MatchesTagExact(InputTag))  
	    {       
		    return Action.InputAction;  
	    }
	}
	
	UE_LOG(LogTemp, Warning, TEXT("InputAction not found for tag [%s] in InputConfig [%s]"), *InputTag.ToString(), *GetNameSafe(this));  
	
    return nullptr;  
}
```

`FindInputActionByTag` 함수는 내부 배열을 순회하면서 전달받은 Gameplay Tag와 일치하는 Input Action을 찾아 반환합니다.

## BaseInputComponent 정의

마지막으로 입력 시스템을 실제 게임 코드와 연결하기 위한 `BaseInputComponent`를 정의해보겠습니다.

앞서 우리는 다음과 같은 구조를 만들었습니다.

```
Gameplay Tag
    ↔
Input Action
    ↔
Input Mapping Context
```

하지만 아직 실제 게임 코드에서는 Input Action을 직접 바인딩해야 하는 상태입니다.

이번에는 이러한 문제를 해결하기 위해 Gameplay Tag 기반으로 Input Action을 바인딩 할 수 있는 `BaseInputComponent`를 구현해보겠습니다.

> Lyra Starter 프로젝트에서는 `UEnhancedInputComponent`를 상속받은 `ULyraEnhancedInputComponent`라는 클래스를 통해 Gameplay Tag 기반의 바인딩 기능을 추가하여 사용하고 있습니다.

이를 통해 게임 코드는 더 이상 특정 Input Action을 직접 참조하지 않고, `"Input.Action.Move"` 와 같은 Gameplay Tag만을 기준으로 입력을 처리할 수 있게 됩니다.

#### BaseInputComponent.h

```cpp
#pragma once

#include "CoreMinimal.h"
#include "EnhancedInputComponent.h"
#include "GameplayTagContainer.h"
#include "InputConfig.h"
#include "BaseInputComponent.generated.h"

class UInputAction;

UCLASS(ClassGroup=(Input), meta=(BlueprintSpawnableComponent))
class UE5_DDD_API UBaseInputComponent : public UEnhancedInputComponent
{
	GENERATED_BODY()

public:
	template <class UserClass, typename FuncType>
	void BindInputActionByTag(
		const UInputConfig* InputConfig,
		const FGameplayTag& InputTag,
		ETriggerEvent TriggerEvent,
		UserClass* Object,
		FuncType Func);
};

template <class UserClass, typename FuncType>
void UBaseInputComponent::BindInputActionByTag(
	const UInputConfig* InputConfig,
	const FGameplayTag& InputTag,
	ETriggerEvent TriggerEvent,
	UserClass* Object,
	FuncType Func)
{
	check(InputConfig);

	if (const UInputAction* InputAction = InputConfig->FindInputActionByTag(InputTag))
	{
		BindAction(InputAction, TriggerEvent, Object, Func);
	}
}
```


#### BaseInputComponent.cpp
```cpp
#include "BaseInputComponent.h"
```


## Player Controller 정의

이제 앞에서 정의한 입력 시스템을 이벤트와 연결하기 위해 `Player Controller`를 구현해보겠습니다.

`Player Controller`에서는 다음과 같은 작업을 수행합니다.

- Input Mapping Context 등록
- Input Config Data Asset 참조
- Gameplay Tag 기반 Input Binding
- 입력 이벤트 처리
#### BasePlayerController.h

```cpp
#pragma once  
  
#include "CoreMinimal.h"  
#include "GameFramework/PlayerController.h"  
#include "BasePlayerController.generated.h"  
  
class UInputConfig;  
class UInputMappingContext;  
struct FInputActionValue;  
  
UCLASS()  
class UE5_DDD_API ABasePlayerController : public APlayerController  
{  
    GENERATED_BODY()  
  
protected:  
    virtual void BeginPlay() override;  
    virtual void SetupInputComponent() override;  
  
protected:  
    UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category="Input")  
    TObjectPtr<UInputConfig> InputConfig;  
    UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category="Input")  
    TObjectPtr<UInputMappingContext> DefaultMappingContext;  
  
    void Input_Move(const FInputActionValue& Value);  
    void Input_LightAttack(const FInputActionValue& Value);  
    void Input_HeavyAttack(const FInputActionValue& Value);  
};
```

#### BasePlayerController.cpp

```cpp
#include "BasePlayerController.h"
#include "EnhancedInputSubsystems.h"
#include "BaseInputComponent.h"
#include "InputActionValue.h"
#include "InputGamePlayTags.h"

void ABasePlayerController::BeginPlay()
{
	Super::BeginPlay();

	if (ULocalPlayer* LocalPlayer = GetLocalPlayer())
	{
		if (UEnhancedInputLocalPlayerSubsystem* Subsystem = LocalPlayer->GetSubsystem<UEnhancedInputLocalPlayerSubsystem>())
		{
			Subsystem->AddMappingContext(DefaultMappingContext, 0);
		}
	}
}

void ABasePlayerController::SetupInputComponent()
{
	Super::SetupInputComponent();

	UBaseInputComponent* BaseInputComponent = Cast<UBaseInputComponent>(InputComponent);
	
	checkf(InputConfig, TEXT("InputConfig is null on %s"), *GetName());

	BaseInputComponent->BindInputActionByTag(
		InputConfig,
		InputGamePlayTags::InputTag_Action_Move,
		ETriggerEvent::Triggered,
		this,
		&ThisClass::Input_Move);
	
	BaseInputComponent->BindInputActionByTag(
		InputConfig,
		InputGamePlayTags::InputTag_Action_LightAttack,
		ETriggerEvent::Triggered,
		this,
		&ThisClass::Input_LightAttack);
	
	BaseInputComponent->BindInputActionByTag(
		InputConfig,
		InputGamePlayTags::InputTag_Action_HeavyAttack,
		ETriggerEvent::Triggered,
		this,
		&ThisClass::Input_HeavyAttack);
}

void ABasePlayerController::Input_Move(const FInputActionValue& Value)
{
	const FVector2D MoveValue = Value.Get<FVector2D>();
	UE_LOG(LogTemp, Log, TEXT("Move: X=%.2f Y=%.2f"), MoveValue.X, MoveValue.Y);
	GEngine->AddOnScreenDebugMessage(-1, 5.f, FColor::Red, FString::Printf(TEXT("Move: X=%.2f Y=%.2f"), MoveValue.X, MoveValue.Y));
}

void ABasePlayerController::Input_LightAttack(const FInputActionValue& Value)
{
	UE_LOG(LogTemp, Log, TEXT("Light Attack Triggered"));	
	GEngine->AddOnScreenDebugMessage(-1, 5.f, FColor::Green, TEXT("Light Attack Triggered"));
}

void ABasePlayerController::Input_HeavyAttack(const FInputActionValue& Value)
{
	UE_LOG(LogTemp, Log, TEXT("Heavy Attack Triggered"));	
	GEngine->AddOnScreenDebugMessage(-1, 5.f, FColor::Blue, TEXT("Heavy Attack Triggered"));
}
```
