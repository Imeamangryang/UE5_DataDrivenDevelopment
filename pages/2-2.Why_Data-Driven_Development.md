
# 데이터 주도 개발

Mike Acton은 [CppCon 2014의 Data-Oriented Design and C++](https://youtu.be/rX0ItVEVjHc?si=yreYGIeGjig5jTN3)강연에서 Data-Oriented Design에 대해 다음과 같이 설명했습니다.

_The purpose of all programs, and all parts of those programs, is to transform data from one form to another._

모든 프로그램과 그 내부의 모든 시스템은 결국 데이터를 어떤 형태에서 다른 형태로 변환하기 위해 존재한다는 의미입니다.

게임 역시 마찬가지입니다.

플레이어의 입력 데이터는 캐릭터의 움직임 데이터로 변환되고, 캐릭터의 상태 데이터는 애니메이션 데이터로 이어집니다. 이후 애니메이션 데이터는 렌더링 데이터를 생성하고, 최종적으로 화면에 출력되는 결과로 변환됩니다.

결국 게임을 구성하는 대부분의 시스템은 데이터를 읽고, 처리하고, 다른 형태의 데이터로 변환하는 과정의 연속이라고 볼 수 있으며, 게임 엔진 역시 결국 데이터를 쉽게 처리하고 변환하기 위한 도구로 생각할 수 있습니다.

# 데이터와 로직의 분리

데이터 주도 개발에서의 핵심은 게임의 구조를 **데이터를 중심으로 바라보고 설계**하는 것입니다.

기존의 코드 중심 구조에서는 게임의 콘텐츠와 동작 방식이 하나의 코드 안에 함께 존재하는 경우가 많았습니다.

예를 들어 캐릭터의 공격력과 같은 값들이 코드 내부에 직접 작성되는 경우가 많았습니다.

```
Character->AttackDamage = 100;
```

이러한 구조에서는 공격력을 수정하기 위해 반드시 코드를 수정해야 하며, 새로운 캐릭터를 추가할 때마다 비슷한 코드가 반복적으로 작성되기 쉽습니다.

하지만 데이터 주도 개발에서는 공격력과 같은 실제 게임 데이터를 코드 밖으로 분리하여 관리합니다.

```
{"CharacterName": "Warrior",    "AttackDamage": 100}
{"CharacterName": "Archer",    "AttackDamage": 80}
```

그리고 코드는 특정 값을 직접 가지는 대신, 데이터를 읽어 동작하는 역할만 수행하게 됩니다.

```
Character->AttackDamage = CharacterData->AttackDamage;
```

이러한 구조에서는 공격력 수치를 변경하더라도 코드를 수정할 필요가 없습니다.  
단순히 데이터만 수정하면 게임의 결과를 변경할 수 있게 됩니다.

즉 데이터 주도 개발은 코드가 게임의 “동작 방식”을 담당하고, 데이터는 게임의 “내용”을 담당하도록 역할을 분리하는 방식이라고 볼 수 있습니다.
